# MusicCutter v3.0｜极速稳定版

适用于 Windows、macOS、Linux 的 **Python + FFmpeg + Excel 可视化音乐裁剪工具**。无需启动网页服务器或将 MP3 上传到网络。

## 先准备环境（只需首次操作）

- 安装 **Python 3.10 或更新版本**。Windows 推荐 Python 官方安装包；如 macOS 系统自带 Python 没有 Tkinter，推荐 Python 官网安装包。Linux 发行版可能还需要 `python3-tk`。
- 安装 **FFmpeg（含 ffprobe）**；音频试听还需要 **ffplay**。可以将三者加入 PATH，或者放到程序旁的 `bin` 文件夹。**程序本身不附带 FFmpeg**。
- 在程序所在文件夹打开终端，执行：

  - Windows：`py -m pip install -r requirements.txt`
  - macOS/Linux：`python3 -m pip install -r requirements.txt`

如果电脑上的命令是 `python` 而不是 `py` 或 `python3`，请按实际情况替换。

## 启动

- Windows：`py music_cutter_gui.py`
- macOS/Linux：`python3 music_cutter_gui.py`

软件会打开桌面图形界面。**没有本地 Web 服务，不需要浏览器、Flask 或其他服务器。**

## 推荐工作流程

1. 点击「**添加音频**」一次选中多首 MP3，或点击「**添加文件夹**」自动扫描文件夹中的音频文件。
2. 从左边选择歌曲。**默认极速模式**只解析所选歌曲的时长，**不会自动解码整个文件生成波形**。
3. 若要看波形，点击「**加载波形（可选）**」，稍候即可在画布上拖动选区；觉得慢可以点击「**取消解析**」。
4. 使用「**开始 (分:秒.1)**」和「**截取秒数**」精确设置。例如 `01:20.5`、`15.0`。精度统一为 **0.1 秒**（最长 40 秒）。
5. 点击「**保存当前片段设置**」——仅在程序内存中记录，不处理音频，也不会卡在 FFmpeg 上。
6. 点击「**试听片段**」——后台启动 FFplay，可以随时「停止试听」或切换其他歌曲；不依赖波形加载成功。
7. 点击「**保存 Excel**」将当前全部片段配置持久化到 `.xlsx` 文件。
8. 点击「**开始批量导出 MP3**」，输出按 Excel/内存参数生成，默认 192kbps。程序会生成 CSV 处理报告。

## 已有 Excel 文件怎么用

点击「打开 Excel」，选择 `裁剪配置模板.xlsx` 的修改版。软件会读取工作表「裁剪任务」；如歌曲找不到，点击「定位源文件」指定文件夹，然后重新操作。

| 原始文件名 | 开始时间 | 截取秒数 | 输出文件名 |
| --- | --- | ---: | --- |
| 遇见.mp3 | 01:20.0 | 10.0 | 001.mp3 |
| 天黑黑.mp3 | 00:45.0 | 15.0 | 002.mp3 |

注意：将 Excel 的**开始时间列设置为文本**，避免 `01:20.0` 被自动识别为日期。表中第三列为数字（秒）。文件名与实际音乐名称须一致，输出名不可重复。

也可以直接在 GUI 中导入音频、设置时间，然后点「保存 Excel」自动生成符合该格式的 `.xlsx`。

## 为什么 v3.0 比前两版更不容易卡住？

- **懒加载**：不再选中一首歌曲就解码整首歌曲。50 首歌曲只导入文件名，不会一次解码 50 首。
- **180 毫秒防抖**：快速连点列表，跳过无用的旧选曲解析，只处理最新选择。
- **独立后台线程**：试听、波形、文件读写、批量导出分别在后台处理；Tkinter 主线程不等待 FFmpeg 完成。
- **可取消 FFmpeg 进程**：切换歌曲或开始试听会终止过期波形任务；试听和导出也支持取消。
- **低负载波形**：只有请求时才用单线程 FFmpeg 和 2kHz 的近似视觉采样生成 640×64 的波形，降低 CPU 和内存占用；**最终输出音乐不使用低采样率，音质不会因此降低**。
- **轻量显示**：只绘制约 200 根线，且保留最近 5 首已加载波形的缓存。
- **状态监控**：底部展示后台任务名称、经过秒数；超过 12 秒没有新阶段信息时显示提示；还可以展开运行日志、复制诊断信息。

特别说明：将时间精度由 0.001 秒调整为 0.1 秒，是为了更简单易用，**不是卡顿的主要原因**；真正改善性能的是按需解析与后台任务管理。

## 运行日志与异常排查

点击「复制诊断信息」，程序会复制操作日志、Python 版本、平台和任务状态。若某个音乐文件仍特别慢，建议检查：

- 歌曲是否位于网盘同步目录、移动硬盘或网络共享目录；优先复制到本地 SSD。
- 关闭「自动加载波形」；先试 `MP3` 文件，确认 FFmpeg 可读取。
- FFmpeg 是不是安装齐全；试听功能单独依赖 FFplay。
- 任务区正在显示“读取时长”“解析波形”“启动试听”“编码 MP3”还是“停止中”；不要把“保存当前片段设置”和“导出音乐”混淆。
- 查看底部日志中的错误详情，若仍长时间无响应，可将复制的诊断日志与问题步骤提供给开发者。

**记录“后台超过 12 秒未更新”并不意味着肯定已经卡死**：某些文件格式可能确实解码缓慢；后台操作有超时和取消机制。

## 只用 Excel 批量处理（不打开界面）

```bash
python music_cutter_gui.py --batch --excel songs.xlsx --input ./input --output ./output
```

Windows 可用 `py`，macOS/Linux 可用 `python3`。如需要覆盖旧的输出 MP3，加 `--overwrite`。这种方式对处理大量歌曲通常更高效。

## 文件与安全

- 原音乐不会被修改；输出会写到单独文件夹。默认不覆盖已有输出文件。
- 失败的剪辑不会保留半成品 MP3；Excel 会先保存到临时文件，再尽可能原子替换。
- 兼容常见格式输入（MP3、WAV、FLAC、M4A、AAC、OGG、OPUS），输出统一为 MP3。
- 没有上传音乐的网络功能；第三方音乐版权请自行确认使用权限。
- 如果在 Windows 上发现被安全软件拦截了 FFmpeg，需允许该程序运行。
